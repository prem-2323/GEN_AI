# Final System Architecture Specification — DocLink Grounded RAG Platform

## Executive Overview
This document specifies the target production architecture for the **DocLink / Document Intelligence** platform, detailing component roles, data flow, hybrid Graph+Vector retrieval fusion, QUBO evidence optimization, fine-tuned QLoRA student LLM inference, and deterministic grounding validation.

---

## 1. Old Architecture vs. New Hardened Architecture

### 1.1 Old Architecture & Problems
The legacy system relied on single-vector naive retrieval without graph context:
- **Naive Vector Search**: High risk of lost context and inability to navigate complex multi-hop document relationships.
- **Unconstrained LLM Hallucination**: LLM generated ungrounded answers without strict citation mapping.
- **Suboptimal Context Window**: Arbitrary top-K selection loaded redundant or noisy chunks into prompt context.
- **No Numerical Validation**: Numbers and dataset metrics generated by LLM were not verified against source evidence.

## 2. Component Roles & Specifications

### 2.1 Neo4j Knowledge Graph (`Neo4jDriverAdapter`)
- **Role**: Captures structural relationships, domain entities, facts, and metrics from ingested documents.
- **Cypher Execution**: Parameterized Cypher queries for deterministic, injection-safe graph traversal.

### 2.2 BGE Embeddings (`BAAI/bge-small-en-v1.5`)
- **Role**: Generates 384-dimensional dense vector representations normalized with L2 norm for cosine similarity.
- **Hardware Acceleration**: PyTorch CUDA execution enabled on GPU.

### 2.3 Persistent FAISS Vector Index (`FAISSVectorStore`)
- **Role**: Provides sub-50ms vector search across indexed document chunks using `IndexFlatIP`.
- **Persistence**: Auto-saves index file (`faiss.index`) and metadata manifest (`metadata.json`).

### 2.4 Reciprocal Rank Fusion (RRF)
- **Role**: Merges vector search ranks $R_{\text{vec}}$ and graph search ranks $R_{\text{graph}}$ into unified score:
  $$S_{\text{RRF}}(c) = \frac{1}{k + R_{\text{vec}}(c)} + \frac{1}{k + R_{\text{graph}}(c)} \quad (k=60)$$

### 2.5 QUBO Evidence Selection (`QUBOFormulator` & `Solvers`)
- **Role**: Formulates evidence selection as Quadratic Unconstrained Binary Optimization:
  $$\min_{x \in \{0,1\}^N} x^T Q x$$
  Balancing semantic relevance, graph connectivity, evidence diversity, and target subset constraint $K$.

### 2.6 Fine-Tuned QLoRA Student Model (`Qwen/Qwen2.5-0.5B-Instruct`)
- **Role**: Parameter-efficient LLM generating concise answers strictly grounded in provided evidence `[E1], [E2]`.

### 2.7 Deterministic Grounding & Numerical Validator (`validate_grounded_answer`)
- **Role**: Verifies citation references, detects invalid evidence IDs, and asserts 100% numerical fact preservation.

### 2.8 Frontend Layer (`React` + `Vite` + `TypeScript`)
- **Role**: Interactive UI rendering grounded answers, source citation badges, QUBO energy metrics, and Grounding PASS status.

## 3. Quantum Hardware Roadmap
The QUBO formulation is structured to seamlessly interface with future D-Wave or Qiskit quantum annealers via the standard $Q$-matrix interface once quantum cloud backends are integrated.
